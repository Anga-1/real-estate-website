# REAL ESTATE WEBSITE

## Product Requirements Document — Version 1.0

**Project Type:** Personal Project / Portfolio Project
**Product Direction:** Generic Real Estate Website
**Status:** Superseded by PRD v2.0

---

# 1. Product Overview

The original concept for this project was a general-purpose real estate website focused primarily on helping users discover and browse property listings.

The website was intended to provide a digital interface through which users could:

* Browse available properties.
* Search for properties.
* View property information.
* Explore property categories.
* Distinguish between properties for sale and rent.
* Contact the relevant party regarding a property.

The initial product direction therefore placed **property discovery and listing presentation** at the centre of the website.

---

# 2. Initial Product Vision

The original vision was to create a modern real estate website that made it easy for users to discover properties that matched their requirements.

The conceptual flow was primarily:

**Search → Browse → View Property → Enquire**

The property catalogue was therefore treated as the primary feature of the website.

---

# 3. Core Website Structure

The initial website was broadly structured around:

```text
Home
│
├── Properties
│   ├── Buy
│   ├── Rent
│   └── Property Details
│
├── Search
│
├── About
│
└── Contact
```

The exact structure was expected to evolve during development.

---

# 4. Property Discovery

Property discovery was a central component of the original product.

Users were expected to browse properties and eventually search or filter them according to relevant characteristics.

Potential filters included:

* Buy / Rent
* Location
* Property type
* Price
* Bedrooms
* Bathrooms
* Property size

The purpose was to make property discovery straightforward and visually accessible.

---

# 5. Property Listings

The original website placed significant emphasis on property listings.

Property cards were expected to communicate information such as:

* Property image.
* Price.
* Location.
* Property type.
* Bedrooms.
* Bathrooms.
* Property size.
* Listing type.
* View property action.

A collection of property cards would form a major component of the website.

# 9. Limitations of the Initial Direction

As development progressed, it became apparent that a generic real-estate website risked becoming conceptually similar to a property marketplace.

This created several problems:

* The product lacked a clearly defined business identity.
* The realtor/client relationship was not sufficiently central.
* Lead generation was not the primary design objective.
* Services such as selling, renting and property consultation were underrepresented.
* Property listings risked becoming the identity of the website rather than supporting a broader business.
* The product could easily drift toward attempting to replicate large property platforms.

These observations led to a revision of the product direction.

---

# 10. Product Direction Change

The project was subsequently redefined around an individual **realtor / real estate agent**.

The revised product focuses on:

**Realtor identity → Services → Property showcase → Lead generation → Qualified inquiry → Viewing**

The generic real-estate website concept represented in this document has therefore been **superseded by PRD v2.0**.
